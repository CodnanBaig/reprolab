# Screenshot provenance

All six PNGs were generated by `tests/browser_memory_test.py` in Chromium during the 2026-09-18 build.

- `desktop-inbox.png`, `mobile-inbox.png`: actual ReproLab inbox with one synthetic recording.
- `desktop-replay.png`, `mobile-replay.png`: actual canvas replay and inspector using a real SDK capture of the isolated synthetic checkout fixture.
- `desktop-login.png`, `mobile-login.png`: actual authentication interface after fixture logout.

The harness inlines the repository's authored CSS and SVG icon. It stubs transport because the managed environment blocks URL navigation. No real customer data, production accounts, third-party images, font files or proprietary source maps appear in these captures.

These images are documentation evidence of rendered local UI, not proof of a live public deployment or an end-to-end network journey. Reproduce with `pnpm run test:browser:memory`; run `pnpm run test:browser` separately in a permitted browser environment.

## Next.js and MongoDB capture — 2026-09-20

`nextjs-mongodb-2026-09-20/` contains Chromium screenshots of every current user-facing surface: sign-in and registration, project creation and selection, empty and populated inboxes, error groups, installation, project settings, the recording sandbox (ready, recording, and saved), session replay, expiring-share creation, and a shared read-only replay.

They were captured with `agent-browser` against a local Next.js development server and the isolated `reprolab_screens_20260920` MongoDB database. The synthetic account, projects, recording, capture keys, and share tokens are disposable test data; the database is dropped after verification, so none remain usable. The checkout failure shown in the recording is the sandbox fixture's intentional 503/error path. These captures contain no customer or production data.
